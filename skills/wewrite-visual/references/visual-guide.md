# 公众号视觉速查

- 封面比例 2.35:1，主体清楚，避免依赖模型生成小字；标题文字由本机渲染保证，
  不要交给生图模型画中文。设计从文章内容长出来，不要套固定版式。
- 封面先定“只讲哪一件事”，一张图一个主角；缩到信息流 360px 宽要能读懂主标题。
- 内文图默认 16:9。只在解释结构、比较、步骤、时间线或提供阅读停顿时使用。
- 每张提示词写清：主体、环境、构图、色板、光线/质感、比例、禁止项。
- 同篇共享 2-3 个主色、同一材质和同一镜头语言；不要混用摄影、扁平插画和 3D。
- 数据图只使用正文已核实的数据。模型不能准确画图表文字时，改为无字示意图。
- 避免水印、平台标识、无来源品牌 logo、密集文字、畸形手部和无关装饰。
- 生成后必须实际打开检查；格式损坏、主体不可辨或内容与文章相反都算失败。

## 封面必须走生成器（不要再手写 HTML）

封面统一用本 skill 自带的 `{skill_dir}/scripts/make_cover.py` 渲染，流程是确定性的：

1. 读完成稿，写 `assets/cover-design.json`，字段见脚本头部说明。
2. 渲染：

```bash
python <skill_dir>/scripts/make_cover.py <文章目录>/assets/cover-design.json \
  -o <文章目录>/assets/cover.png \
  --thumb <文章目录>/assets/cover-thumb.png \
  --html <文章目录>/assets/cover.html \
  --check-palette
```

3. 打开 `cover-thumb.png`（360px）确认主标题仍读得出来，读不出来就加大字号、减少元素重渲染。

### 为什么必须走脚本

**颜色不是问题，复用才是。** 历史上出现过不同文章贴同一张封面：脚本除渲染外还有一道
去重闸门，渲染前扫描项目内所有已有封面，成品若与任何一张逐字节相同就直接报错退出
（`exit 2`），不会写出文件。

- 撞车时先改设计规格，不要用 `--allow-duplicate` 绕过。
- 同一篇文章的多版本草稿（如 `cover-A/B/C.png`）互相重复属正常，不同文章之间重复才是事故。

### 不要复制上一篇文章的脚本

文章目录里如果有一份 `make_cover.py`，**不要拿它当模板**。那些是各自文章留下的副本，
配色和版式都停在当时的状态。照抄会把旧配色一起带到新文章里——这正是「怎么又是这个
配色」的原因。

权威脚本只有一份：本 skill 目录下的 `scripts/make_cover.py`。

### 配色

**不要默认套深青 `#0f766e` + 琥珀。** 那是 `ai-practice` 排版主题的配色，深色大面积铺到
封面上会显得发绿发闷，而且反复使用会让所有封面长得一样。`make_cover.py` 内置的是中性
暖灰默认值；每篇应按内容另定 `palette`，例如：

- 调查/核查类：暖米底 + 墨黑标题 + 朱橙强调
- 事件/争议类：冷白底 + 深蓝标题 + 单一警示色
- 教程/福利类：浅纸底 + 深绿或深棕 + 暖黄点缀

**写 `cover-design.json` 之前，先看一眼最近几篇封面的主色。** 字节级去重拦不住
「同一套配色换文案」——文件不同、看起来一样。加 `--check-palette` 会扫描历史封面的
主色并报出接近的那些。

同一账号的封面应保持字体与版式骨架一致（这是识别度），但底色与强调色随文章主题变化。
